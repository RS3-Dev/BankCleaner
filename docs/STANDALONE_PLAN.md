# Bank Cleaner standalone plan

This records the plan agreed before implementation for making Bank Cleaner a standalone plugin on Bank Core's public API, with the review refinements adopted, and the stages it is built in. Bank Core is used only through its `HOST_CONTRACT.md`; nothing in Bank Core or Bank Tags changes.

## Starting point

- The Cleanup feature was preserved from Bank Utilities `beba274` at `e04dac4`. It was not runnable: its categories forwarded ordinary tag lookups to Bank Utilities' tag store, its page descriptor used Core's removed private page state, and its scan driver lived in the mixed integration code.
- Bank Core (`bankcore`, worktree `fix/pseudo-page-resize` at `2e4941e`) offers owners with pages, tabs, listeners, and bank item snapshots. It has no API version; nothing has shipped.

## Identity

- Plugin `bankcleaner`, Core owner `RegisterExtension("bankcleaner", "Bank Cleaner")`. PrettyUI `6398181` is required; `bankcore` is optional, because the host reports changes only for optional dependencies.
- Every runtime module lives under `bankcleaner/` (`app`, `cleanup/categories`, `cleanup/pages`, `data/*`), so no require path collides with Bank Core's or another plugin's.
- Events `bankcleaner_scan` and `bankcleaner_content`; the reload global `__bankcleaner_session`. Bank Cleaner publishes no API and saves nothing.

## Core encoding

- One rows tab `cleanup` ("Cleanup", icon `ERASER`): heading rows for the three groups (Review, Utility storage, Player-owned house), then one page row per category with a `detail` of its count, or `...` while scanning. 16 rows, within Core's 64.
- 13 pages, within Core's 16, each `{ title = <Label>, key = "cleanup:<category>", layout = rows }`. The key is stable, so a rescan keeps the scroll position.
  - A category without sections: a standard `{ label = <Label> }` row, then one `{ slots = ... }` row.
  - Focus Storage and Spirits: per non-empty section, its label row (`Focus: Recommended`, `Stone Spirits (ore box)`, ...) followed by its slots.
  - No page `heading`: the old custom heading renderer and its offset are gone; the label rows are Core's standard ones, drawn as Bank Tags' labels are.
  - A category with nothing to show is one label row: "None of these items are in your bank."; before the first scan has classified anything, "Scanning bank...".
- Slots are explicit `{ item = objectID, copy = n }`, taken from one `GetBankItems` generation, for stacks with quantity above zero only. Placeholders and catalog-only objects never appear, so a page shows exactly the present stacks of that generation and no ghost.

## Classification

- The legacy rules, catalogs, sections, and quest check are kept unchanged. Every rule reads only the object ID (the quest rule also reads quest completion, failing closed), so results are cached per object.
- On each new generation every layout is rebuilt at once from the snapshot and the cache; only objects not yet classified are evaluated, 25 per logic tick. While new objects are being classified, the pages show the cached objects of the current generation, never an earlier generation's stacks; a withdrawn item leaves its page as soon as the new generation is read.
- A generation that arrives during a scan replaces the scan's target; finished classifications are kept. When `GetBankItems` answers `building`, the last snapshot stays and the next notice is awaited; a closed bank drops the snapshot.
- The cache is cleared whenever the Cleanup tab becomes active with the bank open, so quest progress is checked again, as the legacy plugin rescanned on switching to the tab.
- A page is sent to Core with `UpdatePage` only when its layout changed, and the tab with `UpdateTab` only when a count changed. The scan listener runs only while the Cleanup tab is active or a Cleaner page is shown.

## Lifecycle

- The entry shuts down a previous session found in the same Lua state, evicts its module cache (generated by the build), and connects through the injected `bankcore` or `__bankcore_api`, following `PluginDependencyUpdate`.
- A copy whose owner ID a newer load took retires and never takes it back. Disconnect, Core shutdown, and plugin shutdown stop the scan and drop the handle.
- A plugin panel says whether Bank Core is connected, missing, or replaced.
- No `SetSettings` section and no menus: Bank Cleaner has no preferences.

## Behavior changes from the integrated plugin

- The Cleanup sidebar's category search is dropped; 13 rows do not need it.
- Pages show present stacks only and update with each bank change, rather than keeping stale members as ghosts until a rescan.
- Category labels are Core's standard label rows; there is no custom page heading.

## Repository layout and tools

- `plugins/bankcleaner/` holds the entry and manifest; `bankcleaner/` every runtime module.
- `tools/build.lua`, `check.lua`, and `module_graph.lua` are adapted from Bank Tags, which is only read. The build writes `dist/bankcleaner/` with exactly the modules the entry loads.
- Tests load the real Bank Core, read-only, from `BANKCORE_ROOT`, in Bank Core's stand-in host.
- `reference/` keeps the preserved integration code and tests byte for byte; `cleanup_page.lua` and `lib/core/text.lua`, which the plugin no longer loads, move to `reference/preserved/`. `EXTRACTION_MANIFEST.json` stays unchanged.

## Not verified live

Persistent data scoping (Bank Cleaner saves nothing), when the host calls `PluginDependencyUpdate` on reloads, how the host clones exports, and how label rows and 80-character labels look in the live bank.

## Results

All stages are implemented on `feature/standalone-plugin`, each in its own commit, with `tools/check.lua` passing at every stage against Bank Core `2e4941e` read from `BANKCORE_ROOT`. Bank Core and Bank Tags were only read; their trees were checked unchanged after every stage. Nothing has been verified in the live client.

Tests: `cleanup_categories_test` (every rule, present stacks only, sections, the quest rule failing closed, the batch limit, the cache, forgetting it), `cleanup_pages_test` (page and tab encoding), `cleanup_app_test` (the real Bank Core: tab rows and counts, pages of exact stacks under standard labels with no heading, unchanged pages not sent, withdrawal, new objects, coalesced generations mid-scan, the scan only while in view, forgetting on tab choice, the bank closing), and `plugin_reload_test` (load orders, Core reloading, cloned and unloading, the plugin reloading shared, separate, and hot, and a replaced owner staying idle). Advanced Bank Search's `combined_plugins_test` loads this plugin's build beside it.

Found during implementation and left for review:

- Empty pages first said "Scanning bank..." whenever a new object was being classified, which changed every empty page for each deposit; they now say it only until the first scan since the bank opened or the tab was chosen.
- The build's default `dist` output refused to build once the check had written `dist/check`; Bank Tags' build has the same default. The release output is now `dist/release`.
- Every original file in `EXTRACTION_MANIFEST.json` has a byte-identical copy in the repository: unchanged catalogs in `bankcleaner/data/`, and the adapted `cleanup_categories.lua` and its test in `reference/preserved/`.
